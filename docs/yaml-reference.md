# Справочник YAML-конфигурации CDMBot

CDMBot читает два вида YAML-файлов. Набор сценариев передаётся в `cdmbot program.asm suite.yaml`. Манифест проекта передаётся в `cdmbot project project.yaml`. Оба формата используют `version: 1`.

## Запись значений

- Файл сохраняется в UTF-8, максимальный размер — 1 МиБ. Используйте один YAML-документ с корневым словарём.
- Словарь можно записать блоком с отступами или в фигурных скобках, например `{r0: 10, r1: 20}`. Список можно записать через `-` или в квадратных скобках, например `[r0, r1]`.
- Целые числа можно писать в десятичном виде и с префиксом `0x`. `0x80` — числовой адрес, а `"0x80"` — строка. Флаги принимают целые числа `0` и `1`.
- Имена сценариев, групп и меток — строки. Заключайте в кавычки имена вроде `"on"` и `"yes"`, которые YAML может прочитать как логические значения.
- Для переносимых путей используйте прямые слеши. Относительный путь вычисляется от каталога YAML-файла, в котором он указан.
- Неизвестные поля, повторяющиеся ключи, псевдонимы YAML и значения неверного типа приводят к ошибке. Общие параметры сценариев задавайте через `defaults`.

## Набор сценариев

Ниже приведён рабочий набор для `examples/cdm16/add.asm`. Одна программа может иметь несколько YAML-наборов с разными сценариями.

```yaml
version: 1
architecture: cdm16
memory_model: unified

defaults:
  setup:
    registers: {fp: 0x55aa, sp: 0xfffe}
  run:
    max_steps: 10
  preserve_registers: [r1, fp, sp]
  allowed_register_changes: [r0]

cases:
  simple:
    setup:
      registers: {r0: 0x1200, r1: 0x34}
    expect:
      registers: {r0: 0x1234}
      flags: {c: 0, z: 0}
  wrap:
    setup:
      registers: {r0: 0xffff, r1: 1}
    expect:
      registers: {r0: 0}
      flags: {c: 1, z: 1}
  direct_entry:
    run:
      entry: 0x80
      until: {pc: 0x82}
    setup:
      registers: {r0: 0x7fff, r1: 1}
    expect:
      registers: {r0: 0x8000, pc: 0x82}
      flags: {n: 1, v: 1}
```

### Корневые поля

| Поле | Тип и назначение |
| --- | --- |
| `version` | Обязательное целое число `1`. |
| `architecture` | Обязательная строка `cdm8` или `cdm16`. |
| `memory_model` | `unified` по умолчанию. Образ, данные и стек используют общую память. `harvard` загружает образ в ROM, а входные данные, стек и проверки памяти используют отдельную RAM. |
| `build.harness` | Необязательный путь к вызывающему файлу. Cocas получает обвязку перед основной программой. |
| `build.sources` | Необязательный список дополнительных файлов. Cocas поддерживает исходники, объектные файлы `.obj`, `.o`, `.lib` и библиотеки макросов `.mlb`. Каждый файл указывается один раз. |
| `defaults` | Необязательный словарь с общими настройками сценариев. |
| `cases` | Обязательный непустой словарь вида «имя → настройки сценария». Пустые настройки `{}` проверяют достижение заданного условия остановки. По умолчанию это `halt`. |

Для готового образа `.bin` уберите блок `build` и задавайте входные данные по числовым адресам. Для библиотеки `.mlb` добавьте исполняемую обвязку, которая использует её макросы.

### Наследование `defaults`

Сценарий наследует поля, которые он пропустил. Словари `setup`, `expect` и `run` объединяются по ключам. Внутри `setup` и `expect` словари регистров, флагов, памяти и входов по меткам также объединяются по ключам. Ключ сценария заменяет одноимённый ключ из `defaults`. Списки и условие `run.until` заменяются целиком.

Например, если в `defaults.setup.registers` задано `{r1: 5, sp: 0xf0}`, а сценарий задаёт `{r1: 8}`, он получит `{r1: 8, sp: 0xf0}`. Запись `stack: []` сбрасывает унаследованный список стека. Пустой словарь `registers: {}` сохраняет унаследованные регистры. Блок `defaults` должен быть корректным сам по себе.

### Начальное состояние `setup`

| Поле | Формат |
| --- | --- |
| `registers` | Словарь регистров общего назначения и `sp`. Для точки входа используйте `run.entry`. |
| `flags` | Словарь из `c`, `v`, `z`, `n` со значениями `0` или `1`. Остальные флаги сохраняют состояние после инициализации процессора. |
| `memory` | Словарь «целый байтовый адрес → байт или непустой список байтов». Числовое значение занимает один байт на обеих архитектурах. |
| `stack` | Список целых значений от вершины стека. `stack: [7, 3]` означает, что первые два `pop` прочитают `7` и `3`. |
| `input` | Словарь «уникальная метка → число, строка или список байтов». Метка разрешается при линковке и может быть локальной или экспортированной. |

| Параметр | CdM-8 | CdM-16 |
| --- | --- | --- |
| Регистры общего назначения | `r0`–`r3` | `r0`–`r7`, `fp` — псевдоним `r7` |
| Диапазон регистра, адреса и элемента стека | `0`–`0xff` | `0`–`0xffff` |
| Размер элемента стека и числа в `setup.input` | 1 байт | 2 байта, младший вперёд |
| Адрес вершины при заданном стеке | Любой в пределах RAM | Чётный в пределах RAM |
| Адрес инструкции | Любой в пределах памяти | Чётный в пределах памяти |

Без явно заданного `sp` непустой стек размещается в верхних адресах RAM, а `sp` указывает на первый элемент. Явный `sp` задаёт адрес первого элемента. Стек и блоки памяти должны помещаться в RAM и не пересекаться. В объединённой памяти начальные записи накладываются на образ, поэтому под них нужно зарезервировать место.

```yaml
setup:
  registers: {sp: 0xe0}
  memory: {0x40: [1, 2, 3]}
  stack: [7, 3]
  input:
    start_label: 10
    text_label: "тест\0"
    bytes_label: [0x41, 0x42, 0]
```

Строки в `input` кодируются в UTF-8. В примере нулевой байт задан явно через `\0`. Список байтов записывается буквально, а числовой вход занимает слово архитектуры. При заполнении входов по меткам резервируйте под каждый блок нужное число байтов в ассемблерном файле. [Рабочий пример входов и стека](../examples/cdm8/inputs.yaml)

### Управление запуском `run`

| Поле | Формат |
| --- | --- |
| `entry` | Числовой адрес первой инструкции. По умолчанию CdM-8 начинает с 0, а CdM-16 выполняет штатный сброс по вектору образа. Явный `entry` запускает CdM-16 напрямую. |
| `until` | `halt` по умолчанию. Также принимает `{pc: 0x80}` для остановки перед инструкцией по адресу или `{steps: 3}` для остановки после указанного числа инструкций. |
| `max_steps` | Целое число от 1 до 10 000 000, по умолчанию 10 000. |

`{steps: 0}` и `{pc: адрес_входа}` позволяют проверить начальное состояние. Запрошенное число шагов должно укладываться в `max_steps`. В счётчик входит `halt`, а штатный сброс CdM-16 выполняется до счёта. Если программа остановилась раньше или исчерпала бюджет до достижения условия, сценарий проваливается.

### Проверки результата

| Поле | Что проверяется |
| --- | --- |
| `expect.registers` | Точные значения указанных регистров общего назначения, `sp` и `pc` при остановке. |
| `expect.flags` | Точные значения указанных флагов. |
| `expect.memory` | Содержимое RAM по числовым байтовым адресам. Формат совпадает с `setup.memory`. |
| `preserve_registers` | Перечисленные регистры общего назначения и `sp` в конце совпадают с начальным состоянием. |
| `preserve_memory` | Список диапазонов `{address: начало, length: число_байтов}`. Длина положительная. Проверяется совпадение с начальной RAM. |
| `allowed_register_changes` | Только указанные регистры общего назначения могут менять значение между инструкциями. Временное изменение с восстановлением тоже учитывается. Список `[]` запрещает изменения. |

`allowed_register_changes` отслеживает изменения значения. Запись того же значения по результату инструкции остаётся незаметной. Для контроля итоговой сохранности используйте `preserve_registers`.

## Манифест проекта

```yaml
version: 1
source_roots: [lib]

suites:
  increment:
    program: lib/increment.asm
    suite: tests/increment.yaml

syntax:
  cdm8:
    architecture: cdm8
    directories: [lib]
    files: [tests/harness.asm]

structure:
  directories: [lib, tests]
  files: [tests/increment.yaml]

thresholds:
  file_percent: 66
  line_percent: 100
  comment_percent: 9
```

| Поле | Тип и назначение |
| --- | --- |
| `version` | Обязательное целое число `1`. |
| `source_roots` | Обязательный непустой список каталогов. CDMBot рекурсивно собирает `.asm` и `.mlb` для покрытия. Файлы из пересекающихся корней считаются один раз в общей сводке. |
| `suites` | Необязательный словарь именованных наборов. Каждый набор содержит `program` и `suite`. Архитектура задаётся в YAML набора. |
| `syntax` | Необязательный словарь групп синтаксической проверки. |
| `structure.directories`, `structure.files` | Необязательные списки каталогов и файлов, обязательных для проекта. |
| `thresholds` | Необязательный словарь минимальных процентов покрытия. |

### Как выбрать файлы для проверки синтаксиса

В каждой группе указывается `architecture` и хотя бы один непустой список `files` или `directories`. В каталогах ищутся `.asm` и `.mlb`. `recursive` управляет только поиском в каталогах и по умолчанию равен `true`. Явные и найденные файлы объединяются, повторяющиеся пути учитываются один раз. Отсутствующий каталог или каталог без подходящих файлов проваливает группу.

Эта группа проверяет всё дерево проекта на одной архитектуре.

```yaml
syntax:
  whole_project:
    architecture: cdm8
    directories: [.]
```

Эта группа проверяет файлы непосредственно в корне.

```yaml
syntax:
  root_only:
    architecture: cdm8
    directories: [.]
    recursive: false
```

Можно одновременно задать `directories: [lib, src]` и `files: [tests/harness.asm]`. CDMBot передаёт всю группу Cocas для компиляции. Группируйте файлы по архитектуре и совместимому набору макросов. Синтаксис макроса проверяется при раскрытии в использующем его исходнике. Внешние ссылки проверяются при линковке соответствующего набора.

### Как задать минимальное покрытие

Ключи `thresholds` независимы. Значение — число от `0` до `100` включительно, например `80` или `75.5`. Проценты записываются без знака `%`.

| Ключ | Числитель и знаменатель |
| --- | --- |
| `file_percent` | Файлы с хотя бы одной исполненной строкой / все учтённые исходники из `source_roots`. Подходит для порога на охват всего дерева. |
| `line_percent` | Уникальные исполненные строки инструкций / строки инструкций из карты Cocas. Файлы вне карты влияют на охват файлов. |
| `comment_percent` | Отдельные строки комментариев плюс строки кода с комментарием / все непустые строки. |

Порог применяется к общей сводке проекта. Проверка проходит при фактическом значении, равном минимуму или выше. Если знаменатель равен нулю, метрика недоступна и заданная проверка проваливается, в том числе при минимуме `0`. Сравнение выполняется до округления. Например, `2/3` в отчёте отображается как `66.67%`, но порог `66.67` не проходит.

Провал любого порога даёт проекту код `1`, если нет более приоритетной ошибки с кодом `2`. Чтобы отключить конкретную проверку, уберите её ключ. Пустой или пропущенный блок `thresholds` оставляет покрытие в отчёте без обязательных минимумов.
